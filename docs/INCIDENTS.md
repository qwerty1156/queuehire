# Обращения в поддержку

Ниже — сценарии из вымышленной рабочей среды. Они описывают симптомы,
а не дают список строк кода для исправления.

## QH-101: чужой результат

Компания Beta получила ID задания Alpha из общей переписки.
Beta использовала собственный действующий ключ и смогла прочитать
текст вакансии и результат анализа Alpha.
Также удалось добавить заметку к этому заданию.

Ожидание поддержки: ID не должен быть разрешением на доступ.
Для чужого и отсутствующего задания ответ одинаковый — 404.

## QH-102: клиент повторил запрос

У клиента оборвалось соединение после отправки POST.
Он повторил запрос с тем же `Idempotency-Key` и тем же JSON.
ID задания оказался прежним, но кредитов стало меньше.

Другой клиент попробовал использовать ключ `daily-import`.
Ему вернулся результат другой компании, уже использовавшей такой ключ.

## QH-103: кредиты закончились неожиданно

У компании было 3 кредита. Несколько сотрудников одновременно
отправили задания с разными ключами. Создалось несколько заданий,
хотя кредитов хватало только на одно.

В отдельном инциденте запись в журнал списаний не удалась.
Задание не появилось, но баланс уменьшился.

## QH-104: повторная доставка из очереди

Провайдер временно не отвечал. После исчерпания попыток клиенту
вернули стоимость анализа. Затем то же задание снова попало worker,
и клиенту повторно начислили кредиты.

В логах также встречаются несколько обработок одного успешного задания
и успешный статус вместе с прошлой ошибкой провайдера.
Иногда два worker одновременно берут один job ID.

## QH-105: странный список

В списке с фильтром `status=failed` счётчик включает успешные задания,
а первая страница иногда пустая, хотя подходящие задания существуют.
У крупных аккаунтов список заметно медленнее. В логах много похожих SQL.

## QH-106: кнопка повторить

Frontend уже готов вызвать `POST /v1/jobs/{id}/retry`.
Backend пока возвращает 501. Product согласовал поведение в контракте:
ручной повтор запускает новый оплачиваемый цикл того же задания.
